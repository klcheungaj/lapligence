# The VPI object model catalog of a generated model: every object of the
# IEEE 1800-2009 Clause 37 diagrams (and the coverage and FSM objects of
# 40.5) with its properties, one-to-one relations and iterations, and the
# answer the runtime (llg_vpi.c, llg_vpi_dynamic.c) gives. It is the single
# source of truth for the VPI object model; docs/known_issues.md and
# src/sim/rt/io.md point here. tests/runtime_vpi_catalog.rs checks its
# syntax, that every implemented row names an existing test and that it
# lists every case of the runtime dispatch; adv_019::catalog_walk_matches_the_vpi_catalog
# walks tests/fixtures/sim/feature_completion/adv_019/catalog.sv and checks
# every answer against it.
#
# test <alias> <suite>::<test function>
# node <id> <clause> type=<vpiType>|members=<id>,... [default=<status> <reason>]
#     A type node is one object type (type=NULL: a NULL reference handle);
#     a class node groups other nodes. A type has the rows of its node and of
#     every class that contains it, the nearest declaration of a row winning.
#   <kind> <name> [<status> <detail>]
#     kind: get (vpi_get/vpi_get64), str (vpi_get_str), handle (vpi_handle),
#     iterate (vpi_iterate), func (the routine given as name applies).
#     status (a row without one takes the node default):
#       implemented <test alias>    answers; the test exercises it
#       extension <test alias> <reason>   answers although the diagram does
#                                   not list the row (an llg extension)
#       error <test alias> <reason> the standard error or default is returned
#       unsupported <reason>        applicable but refused with a vpi_chk_error
#                                   error (vpiUndefined, NULL)
#       n/a <reason>                not applicable to what llg supports
# The walk treats every query that no row of the object's type lists as a
# wrong-object query, which must fail with a vpiError error (decision A19-D25).
# vpiType (get, str), vpiLineNo and vpiFile (37.3.2, 37.3.3) apply to every
# object and are not listed.
