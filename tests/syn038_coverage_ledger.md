# SYN-038 coverage ledger

This file holds the machine-checked grammar, context and oracle tables for the
selected synthesis profiles. It is test metadata, not a simulator-support or
acceptance report. Feature status is maintained in
[the simulator feature checklist](../docs/sim_features.md); test methodology is
in [the test guide](readme.md).

`sim_syn038_ledger` reads the section markers and tables below. Preserve stable
IDs, edition gates, fixtures, owners, invocation arguments and expected oracles
when editing. The pair-value denominator is defined by
`tests/syn038_pairwise.json` and
`scripts/check_syn038_pairwise_manifest.py`, which derive the pair catalog in
memory and require zero legal gaps.
Paths in the tables are relative to the repository root.

behavioral owner. Of the 93 stable rows, 87 `PASS` rows are positive Core

compilation mode and observation scope are qualifiers, not additional factors.

Edition, compilation-unit policy, optimizer mode and compile-time/runtime
selection are validation qualifiers attached to witnesses. The native snapshot
drop probe is source-level owned-database evidence; it does not claim public
CLI coverage. Three-way composition chains are separate from the pairwise
denominator and have their own evidence-map rows.

Focal-value attribution follows the checked-in rule bases:

- A function result and its receiving target are distinct slots. Target-side
  observations use `CP=none` and `OP=direct_projection`; an address-only operator
  does not establish an assignment-RHS consumer. `CO=assignment_rhs` requires an
  actual read of that same focal slot on the RHS. An unrepresented outer type
  level does not receive a `TY` factor.
- `SYN038-R-FOCAL-WRITE`, `SYN038-R-READ-SITE`,
  `SYN038-R-REDUCTION-READ`, `SYN038-R-ACTUAL-ADDRESS`,
  `SYN038-R-REF-ACTUAL-VARIABLE` and the continuous-storage rules distinguish a
  source write from its later use. The inout/continuous-variable combination
  remains impossible under these rules.
- `SYN038-R-HIERARCHICAL-CONSTANT` excludes instance-hierarchical constant
  operands, including constant-function and query paths. Package-scope names
  remain lexical; runtime initialization from a hierarchical name is distinct.
  Basis: IEEE 1800-2009 §6.20.2.
- `SYN038-R-PRODUCER-FORMAL-ACTUAL` excludes function results as output/inout
  targets or ref/const-ref actuals, and reduction results as const-ref actuals.
  Copying a result into a separate variable creates a different focal slot.
  Module ref-port projections are not subroutine-actual evidence.
  Basis: IEEE 1800-2009 §13.5.2.
- `SYN038-R-CONST-REF-SOURCE-OP` excludes direct conditional, equality/inside,
  cast/stream and assignment-pattern temporaries as const-ref actuals. Operators
  used only in an index leave an eligible selected variable as a direct
  projection; those controls remain legal.
- `SYN038-R-RUNTIME-DECL-SCOPE` distinguishes module/interface runtime
  declarations from automatic/static subroutine locals, including locals whose
  initializers call functions. Basis: IEEE 1800-2009 §§6.8 and 6.21.
